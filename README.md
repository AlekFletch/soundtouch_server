# SoundTouch Bridge

Возвращает работу кнопок **1–6** на колонках Bose SoundTouch (SoundTouch 10 и 20; проверяется на реальных колонках) после того, как в 2026 году Bose отключила облако SoundTouch.

- Кнопка на колонке или пульте включает выбранную вами интернет-радиостанцию.
- Один мост обслуживает несколько колонок. У каждой свой набор из 6 станций, и набор можно скопировать с одной колонки на другую.
- Станции назначаются через веб-страницу с телефона: поиск по каталогу [Radio-Browser](https://www.radio-browser.info) или своя ссылка на поток.
- Колонку не нужно вскрывать или перепрошивать. Мост работает на любом устройстве в домашней сети: на ПК, Raspberry Pi или Android-планшете с Termux.

Подробный план и текущий статус: [docs/PLAN.md](docs/PLAN.md).

## Как это работает

```
 [кнопка 3 на колонке «Кухня»]
        │  WebSocket ws://кухня:8080 (nowSelectionUpdated, preset id=3)
        ▼
 ┌─────────────── мост (Node.js) ───────────────┐
 │ data/config.json: Кухня, кнопка 3 → «Маяк»   │
 │ UPnP SetAVTransportURI + Play ───────────────┼──► колонка «Кухня»
 │ http://мост:8000/stream/<кухня>/3  ◄── колонка тянет поток
 │        └── прокси https/редиректы/.pls/.m3u ─┼──► сервер радиостанции
 └──────────────────────────────────────────────┘
```

Колонка не умеет воспроизводить `https://`. Поэтому поток всегда идёт через мост: колонка получает обычную `http://` ссылку на мост, а мост сам забирает поток со станции.

## Требования

- Node.js 22 или новее (зависимостей нет, `npm install` не нужен).
- Устройство с мостом и колонка находятся в одной домашней сети.
- Колонка подключена к Wi-Fi (значок Wi-Fi на дисплее).

## Быстрый старт на компьютере

```bash
git clone https://github.com/AlekFletch/soundtouch_server.git soundtouch-bridge
```

```bash
cd soundtouch-bridge
```

1. **Разведка.** IP колонки можно найти в списке устройств роутера.
   ```bash
   node scripts/probe.js 192.168.1.50
   ```
   Когда скрипт перейдёт к WebSocket, нажмите на колонке кнопки 1–6. Все сообщения сохраняются в `data/probe-*.log`.

2. **Тест воспроизведения.**
   ```bash
   node scripts/play-test.js 192.168.1.50
   ```

3. **Запуск моста.**
   ```bash
   npm start
   ```
   Откройте `http://localhost:8000`, добавьте колонки («＋ Добавить колонку»: по IP или кнопкой «Найти в сети») и настройте кнопки каждой колонки.

Настройки задаются переменными окружения или в `data/config.json`:

| Переменная | Назначение |
|---|---|
| `SPEAKER_HOST` | IP колонок через запятую (добавляются, если их ещё нет) |
| `PORT` | порт веб-формы и прокси (по умолчанию 8000) |
| `BRIDGE_HOST` | IP моста, который увидит колонка (по умолчанию определяется автоматически) |
| `UPNP_DESCRIPTION_URL` | адрес description.xml колонки, если поиск через SSDP не работает (при одной колонке в `SPEAKER_HOST`) |
| `SPEAKERS` | полное описание колонок в JSON: `[{"host","apiPort","wsPort","upnpDescriptionUrl"}]` (для эмулятора) |
| `SOUNDTOUCH_API_PORT`, `SOUNDTOUCH_WS_PORT` | порты колонок по умолчанию (8090 и 8080) |
| `CONFIG_FILE` | путь к файлу настроек |

## Разработка без колонки

В проекте есть эмулятор колонки (`scripts/fake-speaker.js`). Он отвечает как настоящая SoundTouch: REST API, WebSocket, UPnP. Как и настоящая колонка, он отвергает `https://` и сам скачивает поток.

```bash
npm run fake-speaker
```

В другом окне запустите мост с параметрами, которые напечатает эмулятор, откройте форму и настройте кнопки. Вторую колонку можно запустить с другими портами: `--api 8092 --ws 18082 --upnp 8093 --name "Кухня" --type "SoundTouch 10"`. В окне эмулятора команды `1`–`6` имитируют нажатие кнопки, `h1`–`h6` — удержание, `s` показывает состояние.

Тесты (unit и сквозной: мост ↔ эмулятор колонки ↔ эмулятор радиостанции, интернет не нужен):

```bash
npm test
```

## Сохранение станции удержанием кнопки

Включите станцию из формы (кнопка «Прослушать») и удерживайте нужную кнопку на колонке, как раньше. Мост увидит, что колонка сохранила пресет, и закрепит станцию за этой кнопкой. *Работает, если колонка разрешает сохранять UPnP-источник в пресет. Это проверяется на шаге 1.*

## Установка на планшет (Android, Termux)

1. Установите из **F-Droid** (не из Google Play, там устаревшие версии) приложения **Termux** и **Termux:Boot**. Один раз откройте Termux:Boot.
2. В Termux выполните:
   ```bash
   pkg install -y git
   ```
   ```bash
   git clone https://github.com/AlekFletch/soundtouch_server.git ~/soundtouch-bridge
   ```
   ```bash
   bash ~/soundtouch-bridge/termux/setup.sh
   ```
   ```bash
   ~/.termux/boot/start-bridge.sh
   ```
3. Настройки Samsung, чтобы Android не «усыплял» мост:
   - *Настройки → Приложения → Termux → Батарея* → «Без ограничений».
   - *Настройки → Обслуживание устройства → Батарея → Ограничения в фоновом режиме* → добавить Termux и Termux:Boot в «Приложения без спящего режима».
   - *Батарея → Дополнительно → Защита батареи* → включить (заряд до 85%, планшет всегда на зарядке).
4. На роутере закрепите за планшетом постоянный IP (резервирование DHCP).
5. С телефона откройте `http://<IP планшета>:8000`.

Лог работы:
```bash
tail -f ~/soundtouch-bridge.log
```

## Ограничения

- HLS-потоки (`.m3u8`) колонка не поддерживает, поэтому в поиске они скрыты.
- Потоки, для которых нужен токен или авторизация, могут не работать.
- Мост должен работать постоянно: без него кнопки не включают станции.
