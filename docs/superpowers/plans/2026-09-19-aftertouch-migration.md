# Миграция колонок на AfterTouch: план

> **Для исполнителя:** используйте superpowers:executing-plans (или subagent-driven-development). Шаги отмечаются чекбоксами. Каждый шаг, меняющий состояние колонки или скачивающий файл, выполняется только после явного подтверждения пользователя в чате.

**Цель:** физические кнопки 1–6 на SoundTouch 10 и SoundTouch 20 снова включают радиостанции.

**Архитектура:** на этом ПК работает сервер AfterTouch (замена облака Bose). Колонки перенаправляются на него по SSH. Собственный мост (`src/`) в этом плане не участвует.

**Стек:** готовый бинарник AfterTouch `soundtouch-service` (Windows amd64), `soundtouch-cli`, Node.js для наших проверочных скриптов.

**Спецификация:** `docs/superpowers/specs/2026-09-19-cloud-emulation-design.md`

## Глобальные ограничения

- Колонки: SoundTouch 10 `10.109.159.11` (прошивка 27.0.6, порт 17000 открыт, SSH закрыт), SoundTouch 20 `10.109.159.179` (прошивка 27.0.6, порт 17000 открыт, SSH закрыт). ПК: `10.109.159.98`.
- Миграция колонок по одной: сначала SoundTouch 10, потом SoundTouch 20.
- Пресеты SoundTouch 20 (6 штук, `LOCAL_INTERNET_RADIO` и `TUNEIN`) нельзя перезаписывать без резервной копии.
- Ссылки пресетов содержат токены станций: в чат и в git их не выводить, файл с копией лежит в `data/` (игнорируется git).
- Скачивание файлов: только после подтверждения (имя, источник, размер).
- Откат всегда должен быть возможен: перед изменением колонки существуют её резервные копии `SoundTouchSdkPrivateCfg.xml` и `/etc/hosts`.

### Task 2: Установка AfterTouch (постоянный хост: планшет Samsung Galaxy Tab S6 Lite, Termux)

> Решение пользователя (2026-09-19): сервер живёт на планшете. Windows-бинарники в `C:\Claude\aftertouch\` (SHA-256 проверен) годятся только для пробного запуска на ПК. Для планшета нужны `soundtouch-service-v0.136.0-linux-arm64` и `soundtouch-cli-v0.136.0-linux-arm64`: та же процедура скачивания (с подтверждением) и проверки SHA-256. Риски Termux: DNS и CA-сертификаты у Go-бинарника (обход через `termux-chroot`), нужен постоянный IP планшета (резервирование DHCP), усыпление Android (см. README, раздел «Установка на планшет»). Шаги ниже написаны для ПК; для планшета пути и запуск заменяются на Termux.

**Files:**
- Create: `C:\Claude\aftertouch\` (вне репозитория)

**Consumes:** ничего.
**Produces:** запущенный `soundtouch-service` на `http://10.109.159.98:<порт>`; колонки достучаться до него могут.

- [ ] **Step 1: Получить подтверждение на скачивание** файлов `soundtouch-service-v0.136.0-windows-amd64.exe` и `soundtouch-cli-v0.136.0-windows-amd64.exe` из `https://github.com/gesellix/Bose-SoundTouch/releases/download/v0.136.0/`, размер пока неизвестен (в описании релиза не указан).
- [ ] **Step 2: Скачать оба файла и файлы `.sha256`, сверить хэши**

```bash
mkdir -p /c/Claude/aftertouch && cd /c/Claude/aftertouch && for f in soundtouch-service soundtouch-cli; do curl -sLO "https://github.com/gesellix/Bose-SoundTouch/releases/download/v0.136.0/$f-v0.136.0-windows-amd64.exe" && curl -sLO "https://github.com/gesellix/Bose-SoundTouch/releases/download/v0.136.0/$f-v0.136.0-windows-amd64.exe.sha256"; done; ls -l
```
Затем сравнить `sha256sum` каждого `.exe` с содержимым его `.sha256`. Не совпало: удалить и остановиться.

- [ ] **Step 3: Освободить порт 8000** (наш мост не запущен; проверить `netstat -ano | findstr :8000`).
- [ ] **Step 4: Запустить сервис** (в фоне), открыть `http://localhost:8000`. SmartScreen и брандмауэр Windows могут запросить разрешение: разрешить входящие только для частной сети.
- [ ] **Step 5: Проверить доступность с колонки:** с ПК `curl http://10.109.159.98:8000/` отвечает; при блокировке брандмауэром показать пользователю правило, которое нужно добавить.
